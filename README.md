# Real Pathfinder (Geode mod, GD 2.2081, Windows)

An auto-pathfinder that plays levels with **Geometry Dash's own physics engine** instead of a copy of it,
so it supports everything the game does: 2.2 objects, triggers, dash orbs, D/J/S blocks, upside-down
slopes, teleport portals, robot, spider, swing, duals and 2-player levels. (Not platformer levels.)

It saves a macro you can load into the **Frame Window Analyzer** mod to measure every click's frame window.

---

## 1. Build it (one time, no coding tools needed)

GitHub builds the mod for you for free.

1. Make a free account at <https://github.com> and sign in.
2. Click **+** (top right) → **New repository**. Name it `real-pathfinder`, set it to **Public**, click **Create repository**.
3. On the new repo page click **uploading an existing file**.
4. Unzip `real-pathfinder.zip` on your PC, open the folder, select **everything inside it** (including the
   `.github` folder — turn on *View → Show → Hidden items* in File Explorer if you can't see it) and drag it into the page.
5. Click **Commit changes**.
6. Open the **Actions** tab. A build called *Build Real Pathfinder* starts automatically (takes ~5–10 minutes).
7. When it shows a green check, click it, scroll to **Artifacts**, and download **Real Pathfinder**. Unzip it —
   inside is `chase.real-pathfinder.geode`.

If the build shows a red X, click it, open the failed step, and send me the error text.

## 2. Install

Put `chase.real-pathfinder.geode` into `geode\mods` inside your Geometry Dash folder
(Steam: right-click GD → Manage → Browse local files). Restart the game.

## 3. Use

1. **Turn off** noclip, speedhack, TPS bypass, Click Between Frames and any bot/replay mod while it runs.
2. Open the level normally (not practice, no Start Pos).
3. Press **Esc → Pathfinder → Start**. The level is hidden and a status screen shows progress:
   - **Best** – furthest any route has reached
   - **Verified** – how far a clean replay from 0% (no checkpoints) has survived
   - **Repairs** – times the clean replay failed and a spot was re-searched in exact mode
4. When it finishes it saves automatically. Press **Esc → Pathfinder** any time to stop and save what it has.
5. Files go to `%LOCALAPPDATA%\GeometryDash\geode\mods\chase.real-pathfinder\macros` (the popup opens the folder):
   - `<level>.json` → import into **Frame Window Analyzer** (pause → Frame Windows → Import)
   - `<level>.gdr.json` → for GDR-compatible bots
6. Exit the level afterwards; the level stays frozen after a search.

### Settings (Geode → Real Pathfinder → settings)
- **Checkpoint Restore** – switch to *Practice-style* if you see lots of repairs on trigger-heavy levels.
- **Work Per Frame** – raise for faster searching (game gets less responsive).
- **Max Checkpoints In Memory** – lower if a huge level runs out of memory.

## How it works
1. It plays with the buttons unchanged until the player dies at tick *D* (1 tick = 1/240 s).
2. It tries button changes at ticks before *D*, latest first, loading saved states to avoid replaying.
3. It continues from the route that got furthest, preferring the middle of each working timing window.
   Routes that keep dying at the same obstacle lose priority, so dead ends get abandoned (backtracking).
4. A finished route is replayed from 0% **without** any saved-state loads. If that clean run dies, the few
   seconds before that point are searched again replaying every try from 0% (exact but slower). The saved
   macro is always one that a clean run completed.

## Status / honesty
- The search engine is tested (`tests/`) on a GD-like test game with cubes, ships, waves, orbs, gravity,
  speed portals, a dead-end trap, and deliberately inaccurate checkpoints.
- The GD code type-checks against the real Geode headers for GD 2.2081, and follows the hook approach the
  Frame Window Analyzer mod verified in-game. It has **not been run inside the game yet** — expect a few
  rounds of fixes. If something breaks, send the newest log file from `geode\logs` inside your Geometry Dash folder.

## Developer notes
- `src/core` – game-independent search (`Search.cpp`) and exporters. `src/game` – GD adapter, hooks, UI.
- `src/game/PlayerFix.hpp` is generated by `tools/gen_player_fix.py` from the bindings; the workflow pins the
  bindings commit it was generated from. Regenerate both together when updating.
- Tests: `cmake -S . -B build-tests -DRPF_BUILD_MOD=OFF -DRPF_BUILD_TESTS=ON && cmake --build build-tests && ./build-tests/rpf_tests`
- Hook approach adapted from [frame-window-analyzer](https://github.com/Iemanddiegamesspeelt/frame-window-analyzer) (MIT).
